High-level business outcomes

What the platform changes for an organisation, in plain terms.

💰 Replace per-workflow SaaS fees with owned infrastructure

n8n enterprise, Zapier, and managed agent platforms charge per seat, per execution, or per workflow. This platform runs on hardware you already own (a workstation, a $7–12/month VM, or pay-per-use AWS serverless). The only recurring cost is LLM tokens — which you would pay anyway.

🔒 Data never leaves your perimeter unless you choose

Self-hosted Postgres, self-hosted engine, agents deployable inside your own network. Documents ingested into knowledge graphs stay in your database. The audit trail records everything — inputs, outputs, per-node events — with no third party in the loop.

⚡ Internal automation shipped in hours, not sprints

A working agent — e.g. an HR FAQ bot grounded on your policy documents, with guardrails — is a drag-and-drop exercise plus one click to deploy. Real example: a hiring pipeline (résumé screener, JD drafter, interview briefer, onboarding FAQ) runs in production on this platform today.

📉 LLM spend is visible and controllable

Per-run and per-node token + cost tracking flows into the audit store. The step-debugger replays cached node outputs instead of re-calling the LLM, cutting iteration cost roughly 4–10× during development — the most expensive phase of agent building.

👍 Quality is measured, not assumed

Deployed agents can collect end-user feedback (👍/👎 + comments). Votes stream back to a central inbox with batch analysis and a Keep / Iterate / Retire recommendation per agent — an evidence-based lifecycle instead of "we think it works".

🚪 No vendor lock-in, at any layer

Workflows are plain JSON. The engine is LangGraph/LangChain — the most widely adopted open agent stack. LLM providers are swappable per node (Anthropic, OpenAI, Google). Deploy targets range from a laptop to AWS. Every component can be replaced independently.

For engineers

Engineering outcomes

The technical capabilities that distinguish this from both no-code tools and DIY scripts.

🐞 Debug agents like code, not like prayers

  • Pin-replay: every node's output is captured per run; re-run skips pinned nodes — iterate on one prompt without paying for the rest.
  • Edit pins: click 📌 → JSON editor → inject hand-crafted data downstream ("what if the RAG node returned garbage?").
  • Breakpoints: right-click → pause before a node, inspect and edit state, resume. Durable via SQLite checkpoints.
  • Re-run from here: pins everything upstream automatically.

🧱 Real control flow, not just chains

  • IF / Switch / Merge / Loop / Wait / Set-Fields / Filter primitives with a safe expression evaluator.
  • Sub-workflows — compose agents from reusable child flows.
  • HTTP Request node with auth presets, 60s/256KiB hard caps.
  • Conditional routing from router / guardrail / if / switch nodes.

🧠 Reasoning strategies as configuration

  • Chain-of-Thought templates (editable, previewable).
  • Tree-of-Thoughts — 3 candidates + LLM judge.
  • Reflexion — draft → critique → revise, genuinely two-step.
  • Self-consistency voting.
  • All selectable per agent node — no code.

📚 Grounding that ships with the agent

  • Knowledge graphs: drop files (PDF/MD/DOCX/TXT) or paste URLs → chunked, embedded into pgvector, visualised as a graph.
  • At deploy time, referenced KGs export as embedded Lance datasets baked into the container — RAG works offline, no phone-home.
  • Provenance per chunk; bind a KG to any agent node.

🔌 MCP-native tooling

  • Catalog of Model Context Protocol servers with one-click presets.
  • “Test tool” dry-runs (initialize + tools/list) before you wire one into a flow.
  • Postman-lite sample-call dialog per tool.
  • Per-deploy MCP health probes from the fleet panel.
  • Tool secrets ship encrypted into the agent container (mcp.env, mode 600).

📜 Audit that survives the network

  • Every run opens/closes an audit record; every node emits events with tokens + cost.
  • Deployed agents buffer locally in SQLite and ship asynchronously — central down ≠ runs blocked; events drain when connectivity returns.
  • Reclaim protocol prunes the edge buffer only after the central ACKs.

📦 Self-contained deploys

  • One bundle = engine image + flow JSON + KG Lance tarballs + MCP secrets + LLM keys.
  • The deployed container needs nothing from the platform at runtime; central URL is swappable live via PUT /config/platform (no redeploy).
  • Bearer-token auth per agent with one-click key rotation from the fleet panel.

🔁 Durable runs (checkpointing)

  • LangGraph SQLite checkpointer persists state after every node.
  • Runs pause at breakpoints and resume — optionally with operator-edited state (human-in-the-loop approvals).
  • Foundation for long-running and queue-driven workflows.

Key design decisions

DecisionRationale
Engine keeps no databaseDeployed agents must be self-contained. Durable state (checkpoints, audit buffer) uses embedded SQLite — same operational profile everywhere.
Workflows are plain JSON (nodes + edges + configs)Versionable, diffable, portable. The same JSON runs in the designer, the workbench, and a baked container.
LangGraph state-merge modelEach node returns a partial dict; the framework merges. Makes pin-replay and checkpointing natural.
Audit is additive and asyncThe run path never waits on telemetry. Lossy only on container death between ACK windows.
Secrets: env-default + DB-overrideapp_settings (AES-GCM encrypted) overrides env at read time — rotate keys from the UI without restarts.

Agent-to-agent

How other AI agents build agents on this platform

The platform is designed to be operated by LLM agents, not just humans. Every layer is discoverable over HTTP, documented in machine-readable form, and automatable end to end.

Discovery surface

URLWhat an agent learns there
GET /docs/PLATFORM_GUIDE.mdThe full platform API manual — how to author resources, deploy, audit. Served as raw markdown over HTTP, written for LLM consumption.
GET /docs/RUNTIME_GUIDE.mdThe runtime surface a deployed agent exposes — base URLs, auth, run/stream/resume shapes, SSE event types.
GET <agent>/agent.mdPer-deploy self-description: this agent's base URL, auth mode, baked flow size, copy-paste snippets in curl/Python/Node. The /llms.txt convention applied to agents.
GET <agent>/openapi.jsonMachine-readable contract for any deployed agent.
GET /api/v1/meta · /diagFeature flags + one-call health across db, engine, keys, deploys.

The canonical loop an agent follows

  1. Authenticate

    Obtain a Personal Access Token (POST /api/v1/api-tokens, scopes: read / write / deploy / admin / feedback). Send as Authorization: Bearer agentic-pat-….

  2. Design — by hand or by prompt

    Either compose flow JSON directly (nodes/edges/configs — schema in PLATFORM_GUIDE), or call the engine's POST /generate with a natural-language description and a complexity level; it returns a complete runnable workflow.

  3. Resolve capabilities

    POST /api/v1/agentic/resolve-flow turns referenced resource ids (prompts, CoT, MCP tools, memory, KGs) into resolved bodies — see exactly what will ship before running.

  4. Test on the shared engine

    POST /workflows then POST /workflows/{id}/run; subscribe to GET /runs/{id}/stream (SSE) for token-level progress. Iterate cheaply with pinned_outputs (replay cached nodes) and interrupt_before (pause, inspect state via GET /runs/{id}, patch via POST /runs/{id}/resume with state_updates).

  5. Deploy

    POST /api/v1/agentic/deploy/local-proxy (SSH + docker + nginx, fully automated), /aws-lambda/execute or /apprunner/execute (real CloudFormation / App Runner provisioning on the operator's AWS account). The response carries the live URL + a one-time API key.

  6. Operate

    Invoke the deployed agent at POST <base>/workflows/baked/run; monitor via the platform's GET /deploy/agents, rotate keys, read the audit trail at GET /api/v1/agent-audit/runs, and act on feedback scores.

Minimal end-to-end example

# 1. AI-design a workflow from a sentence
curl -X POST $ENGINE/generate \
  -d '{"description":"classify support emails, answer billing ones from the KG, escalate the rest","complexity":"intermediate"}'

# 2. Register + run it
WF=$(curl -X POST $ENGINE/workflows -d @flow.json | jq -r .id)
RUN=$(curl -X POST $ENGINE/workflows/$WF/run \
  -d '{"input":"My invoice is wrong","interrupt_before":["escalate"]}' | jq -r .run_id)

# 3. It paused before "escalate" — inspect, patch, resume
curl $ENGINE/runs/$RUN                       # status: paused, node_results so far
curl -X POST $ENGINE/runs/$RUN/resume \
  -d '{"state_updates":{"node_results":{"priority":"P1"}}}'

# 4. Ship it to AWS App Runner for real
curl -X POST $PLATFORM/api/v1/agentic/deploy/apprunner/execute \
  -H "Authorization: Bearer $PAT" \
  -d '{"name":"support-triage","flow_json":"…","region":"us-east-1",
       "ecr_repository":"…","access_role_arn":"…","auth_enabled":true}'
# → {"publicUrl":"https://xyz.us-east-1.awsapprunner.com","apiKey":"shown-once"}
💡 Deployed agents can also call each other: every agent exposes /agent.md + /openapi.json, so an orchestrator agent can discover a fleet of specialist agents and compose them — the platform becomes a registry of callable capabilities.

Honest assessment

Pros & cons

No product is right for everyone. Here is the truthful trade-off list.

✅ Where it shines

  • Total cost of ownership — no per-seat or per-execution fees; runs on a workstation.
  • Debug DX — pin-replay + breakpoints + state editing is ahead of most commercial agent builders.
  • Data sovereignty — everything self-hosted; agents run offline-grounded via Lance.
  • Real deploys — one click to a live URL on own infra or AWS, with auth + audit wired.
  • Agent-operable — machine-readable manuals + PATs + full API coverage mean LLM agents can drive the whole lifecycle.
  • Open stack — LangGraph/LangChain underneath; no proprietary DSL to migrate off.
  • Everything audited — per-node events, tokens, cost, with edge buffering.

⚠️ Where it doesn't (yet)

  • Single-admin — no multi-user RBAC or SSO yet; wrong fit for large shared teams today.
  • Single-host scheduling — no queue mode / horizontal workers; ~hundreds of runs/hour, not tens of thousands.
  • Shared-engine runs are in-memory — the runs list resets on engine restart (audit DB keeps the durable history; checkpoints survive but live resume context doesn't yet).
  • Integration breadth — MCP + HTTP node cover a lot, but there is no 400-connector catalog like n8n/Zapier.
  • AWS deploys need one-time manual prep — ECR image mirror + (App Runner) IAM role; auto-mirroring is on the roadmap.
  • No stack update/delete endpoints yet — redeploying the same name to AWS requires deleting the old stack/service first.
  • Code node is not sandboxed yet — arbitrary Python in flows is intentionally deferred until proper isolation lands.

Quickstart

From clean checkout to a deployed, authenticated, audited agent.

  1. Boot the stack

    cd deploy/local && docker compose up -d → UI at :8888, API :8090, engine :8100, Postgres internal. Set ANTHROPIC_API_KEY (and friends) in .env or later via Settings → keys.

  2. Design a flow

    Designer → drag an Agent node, a Guardrail, connect them — or open Templates, or describe what you want in AI Design. Configure models, prompts, reasoning strategy in the right-hand inspector.

  3. Ground it (optional)

    Knowledge Graph → drop your PDFs / paste URLs → bind the KG to the agent node. Answers now cite your documents.

  4. Run & debug

    Test → Run with an input. Watch nodes light up live. Then iterate: Re-run with pins to skip unchanged nodes; click 📌 to hand-edit a cached output; right-click a node for breakpoints and Re-run from here. Paused runs show a Resume button.

  5. Save

    ⌘S persists to the server (My Workflows). The toolbar shows freshness (“Saved 12s ago”).

  6. Deploy

    Ship → Package & Deploy → pick a target. Local proxy streams its progress live. For AWS, set credentials once in Settings, mirror the image to ECR once, then tick Execute now — the dialog returns the live URL and the one-time API key.

  7. Operate

    Deployed → watch liveness + MCP health; Runs → every execution with cost; Feedback → real user verdicts and a Keep / Iterate / Retire signal. Rotate keys from the fleet panel; repoint the central URL without redeploying if the platform moves.
